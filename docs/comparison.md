# 与 LNPANDY/HGhub-MacOS-iOS-Version 的对比

> 对比对象：<https://github.com/LNPANDY/HGhub-MacOS-iOS-Version>（下称"对方"）
> 对比时间：2026-11-13。结论基于**读对方源码**（Rust / TSX 已下载核对），不是照搬其 README。

## 一、血缘关系：同源，但分叉点不同

```
Minireel/HGhub （原版，已删库）
       │
       ├──► LNPANDY/HGhub-MacOS-iOS-Version   直接派生（fork 原版代码）
       │      Tauri 2 + React 19 + Rust，已到 1.2.2
       │
       └──► vps1986/hghub-clone → 本仓库        行为复刻（重写）
              纯 Python + 单文件 HTML，1.2.0.8
```

- **对方是 fork**：继承原版 Tauri 源码改。
- **我们是复刻**：照留存的 1.2.0 APK 和上游网页重写实现。

我们仓库自身 **0 个 Rust 文件、0 个 TSX 文件**（已核对），与对方没有代码血缘；
共同点只有：同一个上游服务、同一套接口协议、同一个版本基座 1.2.0。

## 二、架构差异（决定一切）

| | 对方 | 本仓库 |
| --- | --- | --- |
| 客户端 | Tauri 2 原生壳 + React；Rust 后端**内嵌在 App 内** | WKWebView / WebView **加载远程网页** |
| 客户端代码量 | Rust ≈14 万字符；前端 25 个文件（`Feed.tsx` 73KB、`SuperResCanvas.tsx` 33KB） | iOS 壳 2 个 Swift 文件 9.8KB；Android 1 个 Java 文件 27.5KB |
| 谁访问上游 | **每台设备直连** `huangguoai.com`（Rust `reqwest`） | **我们的服务器**转发 |
| 需要服务器 | 不需要 | 必须部署 |
| 需要填地址/密钥 | 不需要 | 需要 |
| 换上游域名 | 发新版 App | 改服务端环境变量 |
| 上游 IP 可见性 | 每台设备 IP 暴露给上游 | 上游只看到服务器 IP |

## 三、流量走向（实测，非推测）

本地实测 20 秒播放，按目标域名统计：

| 流量 | 走向 | 说明 |
| --- | --- | --- |
| 视频分片 `.ts` | ✅ **CDN 直连**（`tp8.drleao.cn`） | 最大头，**不占服务器带宽** |
| 播放清单 `.m3u8` | ⚠️ 服务器 `/proxy/m3u8` | 预加载无条件走代理（见下"已知问题"） |
| 封面 | ⚠️ 服务器 `/proxy/img` | 每张解密后约 170KB |
| 列表 / 搜索 / 详情 | ⚠️ 服务器 `/api/*` | JSON，每请求约 20KB |

结论：**视频分片不经过我们的服务器，封面和接口数据经过。** 对方没有服务器，全部由设备直连 + 本地解密。

### 已知可优化项（尚未实施）

1. `preloadPlay()` 预加载清单**无条件走代理**，应尊重 `hg_line` 设置。
2. 封面缺少 `Cache-Control`，每次刷新都重新请求（一次 160 张）。
3. 封面可考虑浏览器端 Cache API 持久化（代码里有但未生效）。

## 五、公平地说

**对方更强的地方**：完整手势与系统横屏桥。其画质增强和播放锁实际上属于网页层能力，
可以适配到本项目 WebView；GPU 增强效果、性能与 HLS 兼容性仍依赖设备实测，不能由架构直接保证。

**本仓库更强的地方**：

- 服务端可控：换线路、加鉴权、加缓存都是改服务器，App 不用重发；
- **对方 README 顶部明确写了"预计近期下线归档/删除"**，本仓库代码自主可控；
- 有完整的 Docker 部署、CI 发版（Nightly / 正式版）、访问密钥体系；
- 对方使用 `PolyForm-Noncommercial` 许可证，商用受限。

## 六、建议

| 目标 | 建议 |
| --- | --- |
| 只要手机刷剧体验 | 用对方的 IPA，别自己造 |
| 学习、可控、自己的服务器 | 保持本仓库，但不要在 iOS 上追平原生体验 |
| 原生体验 + 自建后端 | 保留本仓库的 Python 后端，客户端换 Tauri 壳（工作量大） |
