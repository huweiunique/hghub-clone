# 沉浸观看与紧凑播放器

## 观看方式

- 首页取消顶部搜索栏，视频区域使用完整动态视口；这里的全屏指网页内铺满，浏览器地址栏仍由系统控制。
- 触摸设备默认隐藏导航、标题、右侧操作和静音按钮。首次短暂提示“轻点显示操作 · 上下滑切换”。轻点画面显示操作，再点隐藏；播放中 4 秒无操作自动收起。滚动切剧时收起。暂停、正在拖动进度、菜单、弹层和键盘焦点存在时不自动收起。
- 单击改为显隐操作；暂停使用右侧明确的播放/暂停按钮。原来的双击点赞保留，避免唤出导航时误暂停。
- 底部导航增加搜索，进入搜索页后沿用原有搜索框与热门标签。其它页面保持原有页面结构。
- 视频默认完整显示，保留比例与字幕，不为铺满屏幕强行裁切；比例不一致时保留黑边。
- 桌面鼠标设备默认显示底部导航，鼠标移入或移动时显示视频操作。按精细指针及悬停能力区分，不把所有大屏平板都当桌面。900px 及以上宽屏：首页视频居中，最大宽度 560px；普通列表仍使用原有桌面布局。支持滚轮、上下方向键换剧、空格播放/暂停、Tab 唤出操作、Escape 收起视频操作。

## 全集播放器

- 唤出后两行：播放/暂停、进度、时间；下一集、倍速、声音、横屏、更多。声音与横屏使用 20px 图标，点击区域最低 44px，底色保持克制，关闭按钮保留 48px。
- 线路、画质增强、上一集、收藏、分享、系统全屏、锁定、诊断收进“更多”。仍使用原来的按钮和业务事件，不重建播放或观看历史。
- 全集操作同样在播放中 4 秒无操作后隐藏；暂停、拖动进度或打开菜单时保持显示，恢复播放或操作结束后重新计时。
- 更多面板独立滚动，不挤压视频。点外部或 Escape 关闭，键盘关闭后回到触发入口；面板展开期间保持控制层可见。
- 顶部提供选集、小窗、关闭。选集回原详情，关闭仍走原有进度保存流程。
- 小窗通过能力检测调用 iOS 的 `webkitSetPresentationMode('picture-in-picture')` 或 Chromium 的 `requestPictureInPicture()`。不支持或调用失败时明确提示，并保留系统全屏入口。没有伪造页面浮层冒充系统悬浮窗，也没有添加 Android 原生悬浮窗权限。
- 画质增强、长按临时倍速、锁定、播放恢复与历史继续保留；系统画中画的呈现和画质由系统管理。

## 实现与平台边界

逻辑在 `local_ext/viewing_ui.js`，通过正式补丁脚本注入 Web 与 Android 页面；iOS、Windows、macOS 等访问相同服务页面时共用。上游页面正文不直接修改。旧服务必须更新这份网页扩展，单独重签旧 IPA 不会更新服务端页面。

高频显隐直接切换，不新增过场动画；首页去掉原有缩放和透明度过渡，保持滑动和键盘响应快速。按压采用即时底色反馈，鼠标悬停限定精细指针；没有新增持续动画或额外动效依赖。

## 升级范围与顺序

1. **先升级网页服务。** 必须同时部署已打补丁的 `web/index.html` 和 `local_ext/`，不能只替换首页。代理协议和数据库没有迁移。现有地址、访问密钥、用户观看历史不需要重置。
2. **Docker 部署需要重建镜像并重建容器。** 源码部署在服务器仓库执行 `git pull --ff-only`、`docker compose up -d --build`，保留原有 `.env` 和配置。不需要删除卷、清理数据库或重新生成密钥。若使用镜像仓库部署，须等包含本次提交的新镜像发布后再拉取，代码推送本身不等于镜像已经更新。
3. **iOS 本次 UI 无需重装 IPA。** 当前 WKWebView 从设置的服务端地址加载页面；升级服务端后退出重开 App。小窗使用已有系统能力，本次没有新增原生权限。旧 Nightly 的原生传输、版本显示等问题不在这条 UI 升级结论覆盖范围内。
4. **Android 需要新 APK 与更新后的服务端配套。** 当前 `MainActivity.loadBundledPage` 优先读取 APK 内置 `assets/hghub/index.html`，本次新增 `viewing_ui.js` 的入口也在该内置首页中。只升级服务端不能保证旧 APK 加载这份新扩展。新版 APK 仍需从设置中的服务地址获取扩展脚本，单独安装 APK 也不能代替服务端升级。
5. **Windows、macOS 和其它浏览器端刷新页面即可。** 若使用独立桌面壳，只有确认它加载更新后的服务端页面时才能沿用此结论；若壳内置旧 HTML，则还需更新壳中的页面资源。本仓库没有这类桌面壳的安装包构建目标，不能声称已交付新的 Windows 安装包。

本次代码推送到 `main` 触发后端 CI；APK、IPA 和可选 Docker 镜像由独立 Nightly 流程构建发布。未手动运行 Nightly 时，应等待计划构建；以实际成功产物的提交号核对版本，不能把旧的 Nightly 附件当成本次版本。正式版仍仅由维护者手动打标签发布。
